# 业务证据理解与置信度 Skill

## 目标

解释 PDF 来源匹配和发送记录，并从受控短摘录中识别批准、拒绝、作废、仅供参考、
继续修改、最终版本、已发送未确认或语义不明确等业务证据。

## 执行规则

1. 区分内容匹配、文件哈希、文件名、发送时间和客户确认，不把弱信号等同于强证据。
2. 只有受控摘录明确表达批准时，才能输出 `approved`；不确定时使用 `ambiguous`。
3. PDF 高相似度仅支持来源判断，不自动证明对应可编辑文件是最终主版本。
4. 发送记录未匹配或证据缺失时应明确说明，不为缺失记录推测收件人或发送时间。
5. `target_file_id`、`effective_time` 和 `evidence_refs` 只能复用当前 Task 的
   `evidence_snippets`，引用还必须属于 `artifact_refs` 白名单。
6. 不输出分值、候选排除、自动推荐或人工审核动作；这些动作由确定性规则执行。

## 输出检查

- 摘要同时说明支持性证据和至少一个适用限制。
- 不读取完整邮件、网盘或外部系统；本 Skill 只解释调用方提供的有界摘录和确定性结果。
- 不改变匹配分数、客户确认标记、候选集合或现有证据引用。
