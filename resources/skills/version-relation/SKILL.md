# 版本关系解释 Skill

## 目标

根据确定性比较节点已经产生的结构相似度、内容相似度、关键修改、有界差异证据和排序信号，解释候选文件之间的版本关系，并完成可复核的业务语义分类。

## 执行规则

1. 确定性比较结果是事实来源，不重新计算相似度，也不改变既有父子方向。
2. 优先解释文件名版本号、修改时间、关键字段变化和结构增删如何共同支持现有判断。
3. 信号冲突或证据不足时使用“可能”“暂不确定”等限定语，不把推测写成事实。
4. 分叉、重复和派生关系必须区分说明，不把所有差异都描述为线性升级。
5. 输出引用只能来自当前 Task 的 `artifact_refs` 白名单。
6. 语义分类只能使用输出 Schema 定义的 `change_type`，每项必须给出重要性、旧值、新值、业务影响、证据引用和置信度。
7. `evidence_refs` 只能来自当前输入 `change_evidence`；没有差异证据时不得生成语义分类。
8. 不输出“自动批准”“删除”“发送”等动作，也不直接决定人工审核优先级；优先级由后续规则引擎计算。
9. 版本方向未知时不得猜测旧值和新值。

## 输出检查

- 摘要必须覆盖至少一个关键修改或排序信号。
- 付款期限、金额、责任主体、交付范围和违约责任等业务变化要与纯措辞、格式变化明确区分。
- 不虚构用户确认、发送记录或 PDF 来源证据。
- 不修改确定性节点生成的相似度、置信度和版本边。
